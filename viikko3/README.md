# Week 3 – Bash and a Server Status Report

An automatically updated server status report, generated by a Bash script on my
CSC cPouta virtual machine (Ubuntu) and served by Nginx.

**Live page:** http://195.148.21.16/viikko3/

## Files

| File | Description |
|---|---|
| `report.sh` | Bash script that collects server information and generates the HTML report |
| `crontab.txt` | Cron schedule that runs the script once per minute |

## What the report shows

- Report generation time with time zone (`date`)
- Server uptime (`uptime -p`)
- Root filesystem disk usage in percent (`df -P / | awk ... | tr ...`)
- Disk space status: **OK** below 80 %, **WARNING** at 80 % or above
- Total and available RAM in MiB (`free -m | awk ...`)

## How it works

1. The script stores command output in variables using command substitution `$(...)`.
2. The function `get_disk_status` uses an `if` statement to compare the usage with the 80 % limit.
3. The HTML is written to a temporary file and then moved to
   `/var/www/html/viikko3/index.html`, so visitors never see a half-written page.
4. Cron runs the script every minute. The cron service is enabled in systemd,
   so the schedule continues after a reboot.

## Usage

```bash
chmod +x report.sh
bash -n report.sh        # syntax check
./report.sh --test       # test the disk status logic with 50, 80 and 90
./report.sh              # generate the report
```

Cron schedule (`crontab -e`):

```
* * * * * /home/ubuntu/Linux-Administration/viikko3/report.sh
```
